# Agent Note: SDK cohort 0.2.1-rc.3

Status: implemented

## Problem

The repository pinned the 0.2.1-rc.2 SDK cohort while the supported host and npm `next` moved to 0.2.1-rc.3. The new host adds region-local plugin More menus and changes session draft handling, so the skin center needs both a cohort update and a fresh check of the official token and browser-module contracts rather than a version-literal edit alone.

## Decision

The nine SDK development dependencies stay exact pins and move to `0.2.1-rc.3`. `dsh.engines.dsh` and the `@deepseek-ai/dsh` peer both declare `>=0.2.1-rc.3`, and the English and Chinese README badges carry the same floor with their pairing hashes refreshed. Cordis remains `^4.0.5` and schemastery remains `^3.18.5` because the rc.3 cohort keeps those versions.

The lockfile and release-age ledger describe the installed rc.3 graph, including the new `@deepseek-ai/dsh-client-ui-entry-customization` package. A lockfile audit confirms that every resolved rc.3 package has a matching exclusion.

`contracts/official-tokens-v1.json` is regenerated by `scripts/official-tokens-snapshot.mjs` from the published rc.3 theme and frontend packages. The token set remains exactly 329 entries; only the source cohort changes. `shared/web-platform.ts` likewise keeps the same eleven platform modules and updates only its verification provenance. The existing client inject names and semantic adapter require no source edit, and no wallpaper or renderer source is changed.

## Alternatives considered

**Switch the SDK development dependencies to caret ranges.** Rejected: the exact pins are the repository's reviewed cohort boundary; a caret prerelease range would float to a later host before its token and DOM contracts had been checked.

**Keep the rc.2 token and platform snapshots because their lists are unchanged.** Rejected: the source fields must name the packages actually scanned. The fresh scan is what establishes that no token or module adaptation is needed.

**Patch the skin renderer speculatively for the new More menus.** Rejected: the rc.3 scan and the existing semantic-adapter tests show no removed contract, so speculative DOM changes would add risk without evidence.

## Consequences

`pnpm install --frozen-lockfile --ignore-scripts` passes the supply-chain policy check. `pnpm typecheck`, `pnpm test` (736 tests), `pnpm build`, `pnpm skin-center:check` (62 catalog skins), and `pnpm skin-hooks:check` pass. The rebuilt committed `lib/` is unchanged.

No `@linxin666` version changes and nothing is published to npm. The repository owns its cohort commit; the dsh-web repository moves the submodule pin only after that commit is available on this repository's remote `main`.
