# Agent Note: SDK cohort 0.2.2-alpha.3

Status: implemented

## Problem

The skin center tracked 0.2.1-rc.3 while the supported host moved to 0.2.2-alpha.3. The new host changes Cordis event typings and the official token surface, so the cohort move must include the extension-page helper and the generated design-token contract rather than only dependency literals.

## Decision

SDK development dependencies move to `^0.2.2-alpha.3`, Cordis to `^4.0.6-alpha.2`, and schemastery to `^3.18.6-alpha.2`; the host engine and peer floors are `>=0.2.2-alpha.3`. CI runs Node 24.9.0. The lockfile, release-age ledger, README badges and pairing hashes move together.

The extension-page helper uses erased event parameter types and a cast at its `slots/changed` call site, preserving its existing reconciliation behavior. The official token snapshot is regenerated from the alpha.3 theme and frontend packages: 335 tokens are recorded in `contracts/official-tokens-v1.json` and `src/core/css-safety/official-tokens.generated.ts`.

## Alternatives considered

**Keep the old token snapshot.** Rejected: the skin derivation must learn tokens introduced by the current shell instead of silently treating them as unknown.

**Change skin rendering to match the new host.** Rejected: the platform table and skin contracts need no structural migration beyond the event-signature adaptation and token refresh; rewriting skin assets would be unrelated scope.

**Publish a new skin-center package as part of the cohort move.** Rejected: no release was requested and the package version stays unchanged.

## Consequences

Typecheck and the build pass. The complete suite has 807 passing tests and one Windows-only addon-mapping failure: this Node/Windows run does not report the expected `EPERM` when renaming a directory whose addon is loaded in a child process. That platform behavior is outside the cohort adaptation and is not hidden by weakening the test. Skin catalog and hook checks run separately. No package is published to npm; dsh-web consumes the updated working-tree content through its normal satellite workflow.
