# Agent Note: SDK cohort 0.2.2-rc.1

Status: implemented

## Problem

The skin center tracked 0.2.2-alpha.3 while the supported host moved to 0.2.2-rc.1 (with Cordis 4.1.0 and schemastery 3.19.0). In addition to advancing declarations and refreshing the official token snapshot provenance, `src/core/custom-theme.ts` still emitted `--dsw-specific-sidebar-nav-item-hover`, a token removed from the 0.2.2 official shell surface, causing `tests/custom-theme.spec.ts` to fail its official-token contract assertion.

## Decision

SDK development dependencies move to `^0.2.2-rc.1`, Cordis to `^4.1.0`, and schemastery to `^3.19.0`; the host engine and peer floors move to `>=0.2.2-rc.1`. The lockfile, release-age exclusion ledger, README badges and bilingual pairing hashes move together.

`contracts/official-tokens-v1.json` is refreshed from `@deepseek-ai/dsh-client-ui-theme@0.2.2-rc.1` and `@deepseek-ai/dsh-web-frontend@0.2.2-rc.1` (335 tokens, unchanged token set, updated `source` metadata). The retired `--dsw-specific-sidebar-nav-item-hover` entry is removed from `CUSTOM_THEME_ALLOWED_TOKENS` and `declarations()` in `src/core/custom-theme.ts` (sidebar hover already uses `--dsw-alias-interactive-bg-hover`), and `lib/` is rebuilt.

## Alternatives considered

**Add `--dsw-specific-sidebar-nav-item-hover` back into the official token list by hand.** Rejected: `OFFICIAL_TOKENS` is generated strictly from the shipped official packages and must never invent tokens the shell no longer defines.

**Publish a new skin-center package version.** Rejected: no release was requested and the package version stays unchanged.

## Consequences

`pnpm install --frozen-lockfile --ignore-scripts` passes supply-chain policy verification. `pnpm build`, `pnpm skin-hooks:check`, `pnpm skin-center:check`, script tests and `pnpm typecheck` pass. `tests/custom-theme.spec.ts` (5 tests) now passes, bringing the Vitest suite to 807 passing tests; the single remaining failure is the pre-existing Windows-only native addon directory-rename probe in `tests/css-safety-worker.spec.ts`, which is not weakened. No package is published to npm; dsh-web links the rebuilt working tree locally.
