# 鲸鱼娘 · 雨夜 (Whale Girl · Rainy Night)

[English](README.md) | 中文

暗色专用皮肤，建在**一段背景视频**上：透明伞下的蓝发少女、湿路面上的暖橙街灯散景。
界面画成**雨夜里的一块冷玻璃 —— 只有活着的地方亮着街灯**。每一块面都是薄玻璃、
背后永远是正在落雨的画面，骨架是 1px 冰蓝细线，暖橙留给状态。

它是 [`whale-fantasy`](../whale-fantasy) 的姊妹皮：同一个人物、同一套机壳语言，只差一支颜色。

## 构成

- **纯资产**：`skin.json`（v2 清单）+ `skin.css`（完整重映射 `--dsw-alias-*`）
  + `patches.css`（L3 自由选择器）+ 一段视频。没有 package.json、没有构建步骤、没有 hooks。
- **视频背景**（`backgroundMedia.type = "video"`）：1920x988、851 帧、35.46s、16.55 MB（15.8 MiB）——
  本仓库第二支跑通这条路径的皮肤。
- **暗色专用**：浅色与深色声明同一套暗色值，系统无论要哪一套，渲染出来都相同。

| 夜 | `#0C111A` | 画布，比夜景底色再低一档 |

| 抬起 | `#243247` | 悬停面、药丸、代码块 |
| 结构线 | `#2E5388` | 发基提亮到「1px 细线压在亮画面上还看得见」的那一档 |

| 正文 | `#E8F2F5` | 皮肤底色 |

配色是从画面**量**出来的，不是看着调的：逐帧均值 `rgb(75,93,106)`，**R − B ≈ −33** ——
冷蓝占绝对多数，暖色（`#CB8D76` 一族）只占 **3.2%**。所以暖橙在构图里天生就是稀罕的那一支，
落到屏幕上读起来正是映在玻璃上的城市灯火。

## 背景视频

源片：**35.48s / 1920x1080 / 24fps / 10.35 Mbps / 47.3 MB**，上下各有 **46px 纯黑**
（`cropdetect` 实测 `1920:988:0:46`）。不裁的话 `object-fit: cover` 会把那两条黑边一起铺到视口上。

| 步骤 | 做法 |
| --- | --- |
| 裁边 | `crop=1920:988:0:46` |
| 编码 | **1920 源片原生宽** / 24fps / **CRF 25** / preset slow / **tune film** / level 4.1 |
| 调色 | **不调** —— 不去改作者的素材 |
| 循环 | 尾部 1.2s 淡出到纯黑；源片首帧本来就是纯黑，所以回接处是黑接黑：**851 帧 / 35.458s / 16.55 MB**，回接差 **0.00** |

这条片子是一段四段式的显影，也是它被整段保留的原因：黑 → 描轮廓 → 轮廓里长出网格 →
扫描光带把网格转成完成态 → 约 28 秒的完整画面。

**这次重编是有损的，代价换的是体积。** 这套皮第一版发行的是 48.5 MB / 10.94 Mbps 的档位，
相对源片不降质 —— 但那一个 blob 就占全仓字节数的 41.7%、比其它所有皮肤的 assets 加起来还大，
而本仓没有配 Git LFS，每个克隆都得完整拉它。CRF 25 保住原生宽（这是唯一不该让的那一项），
体积砍到三分之一。

| 档位 | 码率 | SSIM |
| --- | --- | --- |
| 源片视频流 | 11.36 Mbps（15–20s 样品） | 1.0 |
| **CRF 25（发行档）—— 整片 16.55 MB** | **3.73 Mbps（整片实测）** | **0.984** |
| CRF 20 | 8.03 Mbps（15–20s 样品） | 0.990 |
| CRF 14 | 18.39 Mbps（15–20s 样品） | 0.9943 |

发行那一行是**整片自己的算术**（`16,549,139 字节 x 8 / 35.458 s`），不是样品的：这条素材上两者
差约 11%（源片整片视频流 10.35 Mbps，15–20s 样品量到 11.36），而「拿样品码率当整片码率报」
正是上一版把 10.94 Mbps 的文件写成 12.21 Mbps 的原因。SSIM 一律取 15–20s 的亮画面窗口 ——
那是最苛刻的一段；开头 6.5 秒的黑场压缩得好得多（扣掉尾部 29 帧淡出后，整片是 0.985）。

本 README 里其余的实测数字（合成回归、对比度表、截图）都是在第一版 CRF 17 的烘焙上量的。
发行档是同一批 851 帧、相对那段画面 SSIM 0.984，几何一点没动，所以那些读数仍然描述这套皮；
没有重新量一遍。

这套皮的早期版本缩到 1792 宽、用 CRF 28（2.5 Mbps，SSIM 0.9699），肉眼就是糊的，被作者当场抓出来 ——
所以这套皮调的旋钮是 CRF，不是分辨率。**分辨率不要低于源片原生宽**：视频在屏幕上合成到约 1939 CSS px 宽，
原生宽才是唯一 1:1 的选择。

### 两个「差半帧就翻车」的坑

两条都会在朴素判据（回接差 ≤ 帧间差 p95）下**过关**，却留下一条看得见的亮边：

1. **帧数不能按 `Duration` 算。** ffmpeg 打印的只有两位小数：`int(round(35.48 * 24))` 是 852，
   真实是 **851**。多算一帧，淡出被截断在 96.7%，回接差跳到 **4.74**。
2. **淡出的结束时刻要对齐最后一帧的时间戳**（`(frames-1)/fps`），不是「末帧之后那一刻」（`frames/fps`）。
   差这一帧，末帧只到 96.5%、残留 3% 的画面，回接差 **1.69**；对齐之后是 **0.00**。

### 零重编的另一条路

同样的黑边可以完全不重编地去掉：`-c copy -bsf:v h264_metadata=crop_top=50:crop_bottom=50`
只改写 SPS 里的 `frame_cropping` 矩形，画面在**解码时**就被裁掉，码流一个字节不动（45.89 MB，重编 0 次）。
它给不了尾部淡出，所以那条路线的循环每 35.5 秒会硬切一次黑。两套都在作者的构建脚本里留着，
发行的是带淡出的那套。

## 画面被合成器吃掉多少

半透明的皮肤会悄悄把自己的背景压暗，而这件事用眼睛看不出来。量法是：把解码出来的视频帧
与同一帧的上屏截图，在一块纯画面区域上做最小二乘回归 —— **斜率**是还剩多少对比度，
**相关系数**是空间上有没有被抹开。

| | 斜率 | 相关 |
| --- | --- | --- |
| 会话视图（合成后） | **0.967** | **0.970** |
| 其它纯画面区域 | 0.986 – 0.998 | 0.985 – 0.997 |

全套皮**一个 `backdrop-filter` 都没有**。0.97 来自 scrim 在量区上的梯度与壳体自身的合成，不是糊。

## 这套皮修掉的一个真 bug（`whale-fantasy` 里也有）

会话头部那层玻璃原先挂在 `[data-dsh-surface='session-header']` 的 `::before` 上。
**那个元素在真壳里是 `display: contents` —— 它不生成盒子**，于是绝对定位的 `::before`
的包含块一路退到最近的那个定位祖先 `[data-phase='active']`，也就是**整列对话区**（1400x1000）。
一条本该只填 76px 横带的规则，实际在**整片对话区上刷了一层 58% 的夜**。

修之前实测：`screen = 0.412 x video + 21.0`，正好是 `alpha(panel, 0.58)`；把 `[data-slot='main']`
藏掉，同一块区域从 49.4 回到 63.7（解码帧均值 65.0）。把玻璃改挂到**真有那条横带盒子**的元素上
（`[data-slot='conversation.header'] > header`，实测 280,0,1400,76）之后，同一条回归读到 **0.967**。

已经合并的 `whale-fantasy` 带的是同一条旧规则；本 PR 把那边也一起改了
（`skins/whale-fantasy/patches.css`，判据写在文件里的注释里），
现在目录里没有任何一套皮还带着这层纱。

## 全息层

除了 token 重映射，`patches.css` 里那些规则才是把壳体自带的界面变成上面那块仪表的：

- **面** —— 引擎的地面、三处全局压暗、阅读纱全部归零，画面就是地面。面板、菜单、输入卡、
  工具提示、审批卡、设置弹窗、右栏停靠面板全部变成「玻璃 + 1px 细线」；暖色四角括号只出现在入口与浮层上。
- **状态** —— 强调色只花在「活着」的地方：当前行、聚焦中的输入卡、链接、悬停的图标、
  新会话的四角括号、HUD 日志行的左竖条。
- **图标** —— 壳的图标本来就是 1px 线稿，而每一处描边都落在壳自己的五支板岩蓝上；
  现在静息是牌子蓝，悬停／展开／当前转暖。
- **文字** —— 层级由生成器掌管（`label-primary/secondary/tertiary/dimmed/caption`）；
  壳在输入卡与会话头部里又另下了一遍，这两处也重新指回同一套，免得同一个语义层级在两处亮度不同。
- **字体** —— 机壳与读数走 Cascadia Mono、中文走等线 DengXian、显示层走 Bahnschrift；正文散文留在比例字体。

## 可读性

因为阅读纱被整片撤掉了，对比度由文字自己的柔光承担。下面这些数字是**逐字形**量的：
把文字那一层藏掉、两张图相减找出真正的字形像素，只在这些位置上取底色
（取 9x9 邻域的中位，所以柔光算得进去）。

| 元素 | 中位 | 最差 15% |
| --- | --- | --- |
| 助手段落 | 12.1:1 | 7.7:1 |
| 新会话文字 | 10.6:1 | 9.9:1 |
| 用量小卡 | 9.9:1 | 8.0:1 |
| 模型 pill | 8.7:1 | 5.4:1 |
| 过程行 / 工具行 | 3.8:1 | 2.0:1 |
| 输入卡占位符 | 5.5:1（首屏）/ 3.4:1（会话） | 2.5:1 |

唯一可能掉到 4.5:1 以下的是输入卡占位符，而且只在它背后那段画面最亮的地方。
输入卡**故意不铺底**（视频要透出来），这就是这个选择的诚实代价。
