皮肤中心发布 0.4.14，沿用 dsh-web 家族的统一版本号。这是一次纯版本对齐：从 v0.4.13 到本次提交，本仓没有任何插件功能改动，没有皮肤进出目录，SDK 队列与语义属性契约都不动；区间内唯一的内容提交是一份记录皮肤收录轮次的 Agent Note（f4c2992）。与 0.4.13 的唯一代码差异是版本字符串本身——`package.json` 的 `version`，以及构建期由 `__DSH_PKG_VERSION__` 常量烘进 `lib/client.js` 的那一行（`git diff --stat -- lib` 读作 1 insertion / 1 deletion）。`lib/client.js.map`、`lib/index.js`、`lib/css-safety.js`、`lib/css-safety-worker.js` 逐字节未变。

> **兼容性**：本版本没有破坏性变更，没有需要手工迁移的改动，没有重命名任何已持久化的标识符、线协议字段或 profile 格式。以下标识是冻结的：包名 `@linxin666/dsh-client-ui-skin-center`；安装方式（`dsh plugin --profile <name> add` 与 `$DSH_HOME/skins/<id>` 目录布局）；npm `files` 白名单仍只内置 `blue-fantasy`；v2 活跃状态文档的持久化文件名与键名；`data-dsh-skin`、`data-dsh-part` 等语义属性名；线协议字段。`dsh.engines.dsh` 下限保持 `>=0.2.1-rc.3` 未动，与 0.4.13 一致，所以能装 0.4.13 的宿主同样能装 0.4.14，反之亦然。

### 其他改动

- 版本推进到 0.4.14，与 dsh-web 家族的统一版本线一致。本仓只发一个包，`package.json` 的 `version` 是唯一的版本声明；构建产物里唯一的变化是被编译期常量 `__DSH_PKG_VERSION__` 烘进去的版本串，`lib/client.js` 那一行从 `return "0.4.13";` 变为 `return "0.4.14";`，`lib/client.js.map` 与 `lib/index.js` 均未变动。皮肤自身的 manifest 版本不随家族版本走，本轮没有皮肤升版，皮肤目录仍是 62 套
- 记录皮肤收录轮次（f4c2992）：新增 `.agents/notes/implemented/process/2026-11-01-skin-intake-round.md`，把本轮皮肤收录的评审结论与取舍写进决策记录。它不改任何皮肤资产、契约或运行时代码，因此 Reviewed Skin Hooks 的 SHA-256 记录没有位移，62 套皮肤目录也没有增减
- 重建后两道自有门禁照旧通过：`pnpm skin-center:check` 报 `skin-center:check: check OK (62 repo catalog skins; package ships blue-fantasy only)`，`pnpm skin-hooks:check` 报 `skin-hooks-registry: check OK`
- 本地门禁全绿：`node --test scripts/*.test.mjs` 51 项通过，`pnpm typecheck` 无告警退出 0，`pnpm test` 72 个测试文件 808 项通过。构建产物按本仓既有做法随提交入库（`lib/` 在 git 里被跟踪，`pnpm build` 加 `git diff --exit-code -- lib` 是 CI 的那道门），因此本轮提交的范围与 0.4.10 同型：release notes 一份、`package.json` 一行、`lib/client.js` 一行。没有第三类改动混入

> **Compatibility**: this release is not a breaking change. There is nothing to migrate by hand, and no persisted identifier, wire field or profile format was renamed. These identifiers are frozen: the package name `@linxin666/dsh-client-ui-skin-center`; the install path (`dsh plugin --profile <name> add` and the `$DSH_HOME/skins/<id>` directory layout); the npm `files` whitelist, which still ships only `blue-fantasy`; the persisted file name and keys of the v2 active-state document; the semantic attribute names such as `data-dsh-skin` and `data-dsh-part`; and the wire fields. The `dsh.engines.dsh` floor stays at `>=0.2.1-rc.3`, as in 0.4.13, so every host that could install 0.4.13 installs 0.4.14 and the other way round.
