皮肤中心发布 0.4.9，沿用 dsh-web 家族的统一版本号。本版本新增第 62 套皮肤 DIY手账本（`diy-journal` 1.14.1，PR #81），带进了本仓第一份 Reviewed Skin Hooks 记录；同时把 SDK 队列推进到 0.2.1-rc.3，并把语义属性契约补到覆盖 `browser-view` 与 `message-edit` 两个插件。除下面点名的 SDK 下限外，没有对外承诺的变动。

> **兼容性**：本版本没有破坏性变更，没有需要手工迁移的改动，没有重命名任何已持久化的标识符、线协议字段或 profile 格式。以下标识是冻结的：包名 `@linxin666/dsh-client-ui-skin-center`；安装方式（`dsh plugin --profile <name> add` 与 `$DSH_HOME/skins/<id>` 目录布局）；npm `files` 白名单仍只内置 `blue-fantasy`；v2 活跃状态文档的持久化文件名与键名；`data-dsh-skin`、`data-dsh-part` 等语义属性名；线协议字段。唯一落在兼容面上的变动是 `dsh.engines.dsh` 下限：它在 d37711f 里随 SDK 队列从 `>=0.2.1-rc.2` 抬到 `>=0.2.1-rc.3`，低于 rc.3 的宿主不再满足本包的声明。这是对齐官方队列必须付的代价，此后该下限在本版本线内固定。

### 新功能

- DIY手账本（`diy-journal` 1.14.1，PR #81，作者 Alphazerolan）：纸与胶带的拼贴风皮肤，带 14 张 ChatGPT 生成的鲸鱼娘插画、手写体标题、通讯录样式的远程访问对话框、笔记本样式的设置页与浅色/深色两套调色板。可按区域独立选择照片布局、胶带纹样与颜色，支持不设照片、双照片互换以及真实场景预览。本仓皮肤目录从 61 套增至 62 套，`pnpm skin-center:check` 现在报 `62 repo catalog skins; package ships blue-fantasy only`；它不进 npm `files` 白名单，与其余 60 套一样由市场按需安装
- 本仓第一份 Reviewed Skin Hooks 记录：`diy-journal` 的 `hooks.mjs`（227 行）是 v2 契约的 SkinHooks 逃生舱，只做一件事——把运行时状态投影成 `data-cg-*` DOM 属性，视觉全部落在 `patches.css`。它与本机手工放置时走的 `assets/state-projector.js` 是同一套逻辑，靠 `window.__cgStateBooted` 互斥，所以本地自用与市场安装绝不会双跑。`src/reviewed-hooks.generated.ts` 与 `lib/index.js` 各新增 5 行，钉住该皮肤的 manifest 与 hooks 的 SHA-256；`pnpm skin-hooks:check` 是这道门的执行点，钩子字节一变就红

### 修复

- evidence 原图的扩展名与实际编码不符（a17181e）：`diy-journal-light.png` 与 `diy-journal-dark.png` 的载荷其实是 JPEG，改名为 `.jpg` 并同步 `evidence/diy-journal-SHA256SUMS.txt` 的两行文件名。文件内容逐字节未变（git 记为 similarity 100% 的 rename），因此那两行的哈希值本身不变——这条修复只修名字，不动证据

### 其他改动

- 版本推进到 0.4.9，与 dsh-web 家族的统一版本线一致。本仓只发一个包，`package.json` 的 `version` 是唯一的版本声明；构建产物里唯一的变化是 `lib/client.js` 中被编译期常量 `__DSH_PKG_VERSION__` 烘进去的版本串（`git diff --stat -- lib` 是 1 insertion / 1 deletion）。皮肤自身的 manifest 版本不随家族版本走，本轮没有皮肤升版

- README 三甲更新（eb02084）：工坊皮肤分类的前三名换成 maid-atelier、whale-fantasy、whale-song，`blue-fantasy` 退出三甲，同时删掉「`blue-fantasy` 也是本包内置默认皮肤」那句，改为三款都可从创意工坊一键安装；`README.i18n.yaml` 里的中英对照哈希重新登记
- README 标题行修复（aaa972c）：`## Configuration` 被前一段的句尾粘在同一行，拆回独立标题
- Agent Notes 记录两轮收件（f6f8c50、a35b539）：2026-10-20 轮里 `whale-watercolour`（#77）在两次自动关闭后补齐来源与命名说明，并落下 2026-10-17 轮留给它的那个决定——它是目录里第一套 light-only 皮肤，市场在两种模式下展示同一张预览，深色用户会拿到浅色界面；`model-dorm`（#68）仍在等上一轮要的特写。2026-10-21 轮记录 PR #81 的取舍：提交自陈参考角色版权与再分发许可未核实、两处许可清单项未勾选、作者本人请求在澄清前不要合并；所有者要求这一份快速放行，于是本轮要界定「放行」在缺项时仍然能意味着什么

The skin center publishes 0.4.9 on the family's shared version line. It adds the 62nd skin, DIY Journal (`diy-journal` 1.14.1, PR #81), which brings this repository its first reviewed-hooks record; it also advances the SDK cohort to 0.2.1-rc.3 and extends the semantic attribute contract to cover the `browser-view` and `message-edit` plugins. Apart from the SDK floor named below, nothing this package promised moves.

> **Compatibility**: this release is not a breaking change. There is nothing to migrate by hand, and no persisted identifier, wire field or profile format was renamed. These identifiers are frozen: the package name `@linxin666/dsh-client-ui-skin-center`; the install path (`dsh plugin --profile <name> add` and the `$DSH_HOME/skins/<id>` directory layout); the npm `files` whitelist, which still ships only `blue-fantasy`; the persisted file name and keys of the v2 active-state document; the semantic attribute names such as `data-dsh-skin` and `data-dsh-part`; and the wire fields. The one change that does touch compatibility is the `dsh.engines.dsh` floor: commit d37711f raised it from `>=0.2.1-rc.2` to `>=0.2.1-rc.3` along with the SDK cohort, so a host below rc.3 no longer satisfies this package's declaration. That is the price of tracking the official cohort, and the floor stays fixed there for this version line.

### New Features

- DIY Journal (`diy-journal` 1.14.1, PR #81, by Alphazerolan): a paper-and-tape collage skin with 14 ChatGPT-generated Whale-chan illustrations, handwritten headings, an address-book remote-access dialog, notebook-style settings pages, and light and dark palettes. Photo layout, tape pattern and colour are chosen per region, with no-photo areas, two-photo swapping and real scene previews. The repository now carries 62 skin directories instead of 61, and `pnpm skin-center:check` reports `62 repo catalog skins; package ships blue-fantasy only`; the skin is not on the npm `files` whitelist, so it installs on demand from the market like the other 60
- The repository's first reviewed-hooks record: `diy-journal`'s `hooks.mjs` (227 lines) is the v2 contract's SkinHooks escape hatch, and it does one thing - project runtime state into `data-cg-*` DOM attributes, with all visuals living in `patches.css`. It shares that logic with the `assets/state-projector.js` a hand-placed local install loads, and the two are mutually exclusive through `window.__cgStateBooted`, so a local install and a market install never both run it. `src/reviewed-hooks.generated.ts` and `lib/index.js` each gain 5 lines pinning the skin's manifest and hooks SHA-256, and `pnpm skin-hooks:check` is where that gate runs: a single changed byte in a hook turns it red

### Bug Fixes

- The evidence captures carried an extension that did not match their encoding (a17181e): `diy-journal-light.png` and `diy-journal-dark.png` were JPEG payloads, so they are now `.jpg` and the two file names in `evidence/diy-journal-SHA256SUMS.txt` follow. The bytes are identical (git records a similarity-100% rename), which is why the hashes themselves do not change - the fix renames the files and does not touch the evidence

### Other Changes

- The version advances to 0.4.9, in step with the dsh-web family's shared version line. This repository publishes one package, so `package.json`'s `version` is the only version declaration in it, and the only change inside the committed build output is the version string baked into `lib/client.js` by the `__DSH_PKG_VERSION__` compile-time constant (`git diff --stat -- lib` reads 1 insertion and 1 deletion). A skin's own manifest version does not follow the family line, and no skin was versioned in this round
- The SDK cohort advances to 0.2.1-rc.3 (d37711f): nine `@deepseek-ai/dsh-*` devDependencies move from the pinned 0.2.1-rc.2 to 0.2.1-rc.3, and peerDependencies plus the `dsh.engines.dsh` floor follow to `>=0.2.1-rc.3`; `contracts/official-tokens-v1.json` rewrites its `source` field to rc.3 while its 329 tokens keep both count and content; the comment in `shared/web-platform.ts` re-checks the static module table against the rc.3 cohort, which is byte-identical to the 0.2.1-alpha.5 bundle. The new host brings region-local plugin More menus and changed session draft handling, so this round is a contract re-check rather than a version-literal edit; the DSH badges on both README sides move to rc.3 as well
- The semantic attribute contract grows to 90 part rows and 16 plugins (786bd7c, 9a1699d): `message-edit` gains the `entry` and `editor` part anchors and enters the plugin group as a new owner (slot `conversation.chat.turnTail`, entry id `message-edit`); `browser-view` gains 11 part anchors (`panel`, `toggle`, `toolbar`, `address`, `status`, `tabs`, `frame`, `trace`, `empty`, `error`, `tab-title`) and one plugin row (owner `dsh-browser-view`, the key of the right pane's `sidebar.right.pane.tab` and `.title`). The part group goes from 78 rows to 90 and the plugin group from 14 to 16, so a skin can hang its visuals on specific parts of these two plugins instead of guessing their class names
- The README top three is updated (eb02084): the Workshop skin category's first three become maid-atelier, whale-fantasy and whale-song, `blue-fantasy` leaves the trio, and the sentence calling `blue-fantasy` this package's built-in default is dropped in favour of all three installing from the Workshop in one click; `README.i18n.yaml` records the refreshed bilingual hash pair
- A README heading is repaired (aaa972c): `## Configuration` had been glued to the end of the preceding paragraph and is back on its own line
- Agent Notes record two intake rounds (f6f8c50, a35b539): in the 2026-10-20 round `whale-watercolour` (#77) returns after two automatic closes with its provenance and naming answered and settles the decision the 2026-10-17 round left open - it is the catalog's first light-only skin, so the market shows the same preview in both modes and a dark-mode user receives a light interface; `model-dorm` (#68) still waits on the close-up the previous round asked for. The 2026-10-21 round records the trade-off behind PR #81: the submission itself states that reference-character rights and redistribution permission are unverified, leaves both licensing checklist items unchecked, and asks reviewers not to merge before that clearance is resolved; with the owner asking for a quick pass-through, the round had to define what "waved through" can still mean when a gate item is withheld
