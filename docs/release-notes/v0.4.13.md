The skin center publishes 0.4.13 on the family's shared version line. This release isolates CSS safety transforms inside short-lived worker processes to resolve Windows file-lock errors (`EPERM`) caused by lightningcss native addons during plugin installation, and registers semantic attribute contracts for the built-in plugin group and plugin manager surfaces.

> **Compatibility**: This release contains no breaking changes and requires no manual migration. The package name `@linxin666/dsh-client-ui-skin-center` and installation layout are unchanged; npm `files` still ships only `blue-fantasy`; `dsh.engines.dsh` and `@deepseek-ai/dsh` peer dependencies remain `>=0.2.1-rc.3`. The package root stops exporting the transform function in favor of the `./css-safety` subpath export, which market builds and CLI scripts now target.

### Bug Fixes

- Isolate CSS safety transforms in short-lived worker processes (66ec9f1): Fixes issue #98 on Windows where lightningcss native addons mapped into the DSH host process blocked plugin manager package renames with `[ERR_PNPM_EPERM]`. The host process never loads native addons; transforms run serially in child worker processes over IPC and exit immediately after replying, freeing file locks for package installation

### Other Changes

- Register built-in group scope and owner parts (07b684e): Adds the toggle control and contributing bundle line of the built-in plugin group to `contracts/semantic-attrs-v1.md` and corrects the table count
- Register plugin manager semantic attributes (feca0b8): Registers the update-check toolbar and built-in plugin group attributes injected into the official Plugins page
- Advance version to 0.4.13: Aligns with the family version line, rebuilding and verifying `lib/` artifacts
