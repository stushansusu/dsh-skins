皮肤中心发布 0.4.11，沿用 dsh-web 家族的统一版本号。本版本把皮肤页挂进「Web 扩展」父页（PR #95），并把设置卡在宽容器里重排成两栏；皮肤目录、钩子记录与 npm 白名单都不动，62 套皮肤照旧只内置 `blue-fantasy`。除下面点名的座位变化外，没有对外承诺的变动。

> **兼容性**：本版本没有破坏性变更，没有需要手工迁移的改动，没有重命名任何已持久化的标识符、线协议字段或 profile 格式。以下标识是冻结的：包名 `@linxin666/dsh-client-ui-skin-center`；安装方式（`dsh plugin --profile <name> add` 与 `$DSH_HOME/skins/<id>` 目录布局）；npm `files` 白名单仍只内置 `blue-fantasy`；v2 活跃状态文档的持久化文件名与键名；`data-dsh-skin`、`data-dsh-part` 等语义属性名；线协议字段。`dsh.engines.dsh` 下限保持 `>=0.2.1-rc.3` 未动，与 0.4.10 一致。「Web 扩展」父页缺席时，皮肤页仍是一级设置分区（id `skin-center`、order 120），独立安装看到的界面与 0.4.10 逐像素相同。

### 新功能

- 设置页挂进「Web 扩展」父页（79d1244，PR #95，作者 Nwflower）：父页发布 `webUiExtensions` 服务时，皮肤页以 keyed 槽 `web-ui.extension`、key `skin-center` 注册进去，入口变成 设置 → Web 扩展 → 皮肤；服务缺席时回落到一级 `settings.section` 的 id `skin-center`、order 120（`src/client/extension-seat.ts`），独立安装保留原入口。迁移由一个槽变更对账循环独占，任何时刻只有一份存活条目，两个座位不会同时出现；keyed 注册不带 list 专属的 id、order 与 label。设置卡根暴露 `data-dsh-plugin="skin-center"`，皮肤可以把装饰挂在卡上而不必猜类名
- 宽容器两栏布局（3a6956e、76a0dae）：卡片正文在宽容器里是两栏网格，主栏放库工具条、委派皮肤行、预览网格与自定义主题，侧栏留给背景与模糊这组紧凑控件；窄容器回落单栏，预览网格保持响应式。宽度靠 CSS 容器查询（`container-type: inline-size`）测量而不是读 viewport，所以同一份卡片在设置弹窗与独立页面里都不会错栏
- 分段控件与步进控件（e15ffd1、76a0dae）：`SegmentGroup` 用一个真实药丸元素在选项间滑动，每次摆放按容器的内边距盒测量当前按钮，再由 CSS 过渡 x/y/宽高，所以控制折到第二行时药丸仍落在正确那一行；`ResizeObserver` 在组或选项尺寸变化时重新测量，首次摆放不动画。`StepperControl` 对齐宿主字号设置那种步进器，配粗档滑块与 `RangeBubble` 数值气泡，值按步长取整以避免 0.3 + 0.1 一类的浮点漂移
- 语义属性契约补到 Web 扩展父页与子页锚点：`web-ui-settings` 新增 `extensions`（父级根，一级 `settings.section` id `web-ui-plugins` 的内容容器）与 `tabs` / `tab` / `panel`（二级 TAB 导航、TAB 按钮与当前页面容器，`[role="tablist"]` / `[role="tab"]` / `[role="tabpanel"]`）；`skin-center` 新增 `panel`（`[data-dsh-plugin="skin-center"][data-dsh-part="panel"]`）。plugin 组里 `pet`、`usage`、`dsh-web-ui-market`、`skin-center` 四行改写为双席位描述：Web 扩展内的 keyed id，独立安装时的一级 `settings.section` id

The skin center publishes 0.4.11 on the family's shared version line. It seats the skin page inside the Web Extensions parent (PR #95) and rearranges the settings card into two columns on wide containers; the skin catalog, the reviewed-hooks record and the npm whitelist do not move, and the 62 skins still ship only `blue-fantasy` inside the package. Apart from the seat named below, nothing this package promised changes.

> **Compatibility**: this release is not a breaking change. There is nothing to migrate by hand, and no persisted identifier, wire field or profile format was renamed. These identifiers are frozen: the package name `@linxin666/dsh-client-ui-skin-center`; the install path (`dsh plugin --profile <name> add` and the `$DSH_HOME/skins/<id>` directory layout); the npm `files` whitelist, which still ships only `blue-fantasy`; the persisted file name and keys of the v2 active-state document; the semantic attribute names such as `data-dsh-skin` and `data-dsh-part`; and the wire fields. The `dsh.engines.dsh` floor stays at `>=0.2.1-rc.3`, as in 0.4.10. Where the Web Extensions parent is absent the skin page is still a first-level settings section (id `skin-center`, order 120), so a standalone install looks exactly as it did in 0.4.10.

### New Features

- The settings page seats itself in the Web Extensions parent (79d1244, PR #95, by Nwflower): when the parent publishes the `webUiExtensions` service, the skin page registers with it under the keyed slot `web-ui.extension` with key `skin-center`, and the entry becomes Settings -> Web Extensions -> Skins; without that service the page falls back to the first-level `settings.section` with id `skin-center` and order 120 (`src/client/extension-seat.ts`), so a standalone install keeps its original entry. One slot-change reconciliation loop owns the migration and keeps exactly one live entry, so the two seats never coexist; keyed registrations carry no list-only id, order or label. The settings card exposes `data-dsh-plugin="skin-center"`, so a skin can hang decoration on the card instead of guessing class names
- A two-column layout on wide containers (3a6956e, 76a0dae): the card body becomes a two-column grid when there is room, with the library toolbar, the delegated rows, the preview grid and the custom theme in the main column and the background and blur controls in a compact side column; narrow containers restore one column and the preview grid stays responsive. Width is measured with a CSS container query (`container-type: inline-size`) rather than the viewport, so the same card lands in the right columns in a settings dialog and on a standalone page alike
- Segmented and stepper controls (e15ffd1, 76a0dae): `SegmentGroup` moves one real pill element between options. Each placement measures the active button against the group's padding box and lets CSS transition x, y, width and height, so a control that wraps onto a second line still lands the pill on the right row; a `ResizeObserver` re-measures when the group or an option changes size, and nothing animates on the first placement. `StepperControl` matches the host's own font-size setting control, with a coarse slider and a `RangeBubble` value bubble, rounding stepped values so the 0.3 + 0.1 kind of float drift does not appear
- The semantic attribute contract grows to the Web Extensions parent and child anchors: `web-ui-settings` gains `extensions` (the parent root, the content container of the first-level `settings.section` id `web-ui-plugins`) and `tabs` / `tab` / `panel` (the second-level TAB navigation, the TAB buttons and the current page container, `[role="tablist"]` / `[role="tab"]` / `[role="tabpanel"]`); `skin-center` gains `panel` (`[data-dsh-plugin="skin-center"][data-dsh-part="panel"]`). In the plugin group the `pet`, `usage`, `dsh-web-ui-market` and `skin-center` rows are rewritten as dual-seat descriptions: the keyed id inside Web Extensions, and the first-level `settings.section` id a standalone install sees

### Bug Fixes

- A plugin-look card title is no longer squeezed by its badge, and narrow containers no longer overflow (b66fe9b): the delegated-skin card's title row can shrink, the badge keeps a fixed width, and a narrow title wraps instead of pushing the row out of the card

It still takes no grid cell, because a cell exists to show a preview image and this package holds none for a look another plugin paints. The page copy is shortened throughout, the tagline that duplicated the catalog is dropped, and the wallpaper and delegated-skin explanations are each cut to one line
- DIY Journal's settings decorations switch to semantic panel roots (`skins/diy-journal/patches.css`): the first-level navigation `button:nth-child(7..11)` positional selectors become `:has([data-dsh-plugin="..."])`, and the Web plugins illustration additionally excludes a shared parent that contains the skin, pet, Workshop or usage child pages, so the parent no longer masquerades as the Web plugins TAB. Settings decoration stops moving when the navigation roster changes
- Two evidence captures (5bee5b6): `evidence/skin-center-settings-light.png` and `evidence/skin-center-settings-dark.png`, real captures of the settings page in light and dark, committed with the repository
- Both README sides point at Settings -> Web Extensions -> Skins, and the acceptance checklist sentence follows; `README.i18n.yaml` records the refreshed bilingual hash pair. Agent Notes record the 2026-10-26 seat decision and the three alternatives it rejected (dropping the legacy seat, splitting background controls into their own settings section, keeping positional illustration selectors)
- The version advances to 0.4.11, in step with the dsh-web family's shared version line.
