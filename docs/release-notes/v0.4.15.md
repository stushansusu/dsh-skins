皮肤中心发布 0.4.15，沿用 dsh-web 家族的统一版本号。本版本把 SDK 队列推到 DSH 0.2.2-rc.1 并随之收紧宿主下限，把 verdandi 输入卡下方那条读数条收成一张纸面上的一行，随 dsh-git-graph 离队退役全部 Git 图谱样式规则，并在语义属性契约里登记 diagrams 插件与它拥有的 diagram part。皮肤目录仍是 62 套，Reviewed Skin Hooks 记录与 npm 白名单都不动，包内照旧只内置 `blue-fantasy`。

> **兼容性**：本版本有一处收紧需要先看：`dsh.engines.dsh` 与 `@deepseek-ai/dsh` 对等依赖的下限从 `>=0.2.1-rc.3` 提到 `>=0.2.2-rc.1`，低于该版本的宿主装不上 0.4.15，要先把宿主升到 0.2.2-rc.1 或更高。除此之外没有破坏性变更，没有需要手工迁移的改动：包名 `@linxin666/dsh-client-ui-skin-center`；安装方式（`dsh plugin --profile <name> add` 与 `$DSH_HOME/skins/<id>` 目录布局）；npm `files` 白名单仍只内置 `blue-fantasy`；v2 活跃状态文档的持久化文件名与键名；`data-dsh-skin`、`data-dsh-part` 等语义属性名；线协议字段——全部未改名。已保存的自定义主题 profile 字段一个不改，只是生成的 CSS 少一条退役令牌声明。语义属性契约里 git-graph 那五行 part 随插件离队删除，新增 `diagram` 一行。

### 新功能

- 跟进 DSH 0.2.2 队列（932b010、47705d4）：SDK 开发依赖先钉到 0.2.2-alpha.3、再钉到 0.2.2-rc.1，Cordis 到 `^4.1.0`、schemastery 到 `^3.19.0`，`dsh.engines.dsh` 与 `@deepseek-ai/dsh` 对等依赖的下限同步提到 `>=0.2.2-rc.1`，CI 与 release 两个工作流的 Node 从 22 换到 24.9.0。Cordis 改了事件签名，`src/client/web-extension-page.ts` 的 `ctx.on` 因此改用擦除后的参数类型并加一次调用点 cast，`slots/changed` 对账行为不变。官方令牌快照按 `dsh-client-ui-theme@0.2.2-rc.1` 与 `dsh-web-frontend@0.2.2-rc.1` 重新生成，329 条增至 335 条：新增 `--dsw-alias-illustration-background`、`-backing`、`-detail`、`-inset`、`-shadow`、`-surface` 六条插画令牌与 `--dsw-alias-state-done-primary`，删除官方外壳已撤掉的 `--dsw-specific-sidebar-nav-item-hover`；README 徽标与中英配对哈希同步

### 修复

- 读数条合成一张纸面（c616ade）：宿主把上下文环渲染成 `[data-slot="conversation.composer.dock"]` 包装的同级兄弟而不是它的子元素，旧写法把纸面外壳画在 slot 包装上，环就被留在了面板右端之外，读数条读作两块割裂的东西。外壳改画在 `[data-composer-dock]` 容器上，两张读数在左、上下文环在右，落在同一张纸上；那条给已不存在属性 `[data-dsh-live-tps]` 写的右对齐规则一并删除
- 上下文环不再像贴在纸面右端的贴片（8737ca7）：外壳主题给环的触发器留着它自己的药丸底色与圆角，那层规则赢过按钮自己的透明背景。现在把环整棵子树的 `background` 与 `box-shadow` 归零，只保留金线分隔，环与两张读数落在同一张纸上
- 读数条改为单行并按内容收窄（4c827c1、026b491）：两枚读数药丸并肩、中间一道金色细线、上下文环在最右收尾，读作一行状态而不是两处读数；输入卡放不下时整行折行，读数不被裁切。宽度从铺满输入卡改成 `width: max-content` 并封顶 `max-width: 100%`，三格从左侧成组，中间不再留一大块空白
- 自定义主题停发退役令牌（47705d4）：官方外壳在 0.2.2 撤掉 `--dsw-specific-sidebar-nav-item-hover` 之后，`src/core/custom-theme.ts` 仍在亮暗两块里各生成这一条。`OFFICIAL_TOKENS` 只接受从官方包抓到的令牌、不手写补回，所以改的是生成侧：`CUSTOM_THEME_ALLOWED_TOKENS` 与 `declarations()` 一起删掉这一条（侧边栏悬停本就走 `--dsw-alias-interactive-bg-hover`），`tests/custom-theme.spec.ts` 的官方令牌契约断言因此重新成立。皮肤里仍声明这条令牌的地方不经由这张表，不受影响

### 其他改动

- 退役 Git 图谱样式规则（773fe20）：dsh-git-graph 离开家族，`[data-gitgraph-*]` 选择器、`data-dsh-plugin="git-graph"` 注入与契约里它那五行 part 都不可能再被产出，属死代码。15 套皮肤的 `patches.css` 随之瘦身（`blue-fantasy`、`cyber-night`、`dragon-heir`、`furina`、`matrix`、`miku`、`minecraft`、`remiel-starlit`、`war-thunder`、`whale-song`、`xp` 各删去整段图谱样式，`claude`、`diy-journal`、`summer-liquid-glass`、`wallpaper-exclusive` 删去其中的图谱引用），`src/client/runtime/semantic-adapter.ts` 的两条注入规则与两个锚点属性移除，v1→v2 迁移脚本里铸造 `chip` 与 `dialog` 两个 part 值的映射删除，`pink-sakura` 描述里的「Git 图谱」字样去掉（皮肤版本仍是 1.1.0），`pink-sakura`、`remiel-starlit`、`wallpaper-exclusive` 的中英 README 一起改口径。`lib/` 与 Reviewed Skin Hooks 登记重新生成，钩子记录本身无位移。视觉上没有任何变化：这些规则本来就已经匹配不到元素
- 契约登记 diagrams 插件与图示 part（be28253）：新的 dsh-diagrams 把 mermaid 代码块渲染进自己的容器，契约于是登记 `diagrams` 插件行与它拥有的 `diagram` part（`[data-dsh-plugin="diagrams"][data-dsh-part="diagram"]`，外观由 mermaid SVG 自带，原始代码块只隐藏、不在皮肤面内）。part 组表头行数从 103 变成 99：删掉 git-graph 五行、加上 diagrams 一行
- 版本推进到 0.4.15，与 dsh-web 家族的统一版本线一致。本仓只发一个包，`package.json` 的 `version` 是唯一的版本声明；`lib/` 按本仓既有做法随提交入库，本轮源码未动，重建后 `git diff --stat -- lib` 读作 `lib/client.js | 2 +-`（1 insertion / 1 deletion），那一行从 `return "0.4.14";` 变为 `return "0.4.15";`，`lib/client.js.map`、`lib/index.js`、`lib/css-safety.js`、`lib/css-safety-worker.js` 逐字节未变

The skin center publishes 0.4.15 on the family's shared version line. It moves the SDK cohort to DSH 0.2.2-rc.1 and tightens the host floor with it, folds the strip under the verdandi composer into one row on one sheet, retires every Git graph style rule now that dsh-git-graph has left the family, and registers the diagrams plugin and the diagram part it owns in the semantic attribute contract. The catalog still holds 62 skins, the Reviewed Skin Hooks record and the npm whitelist do not move, and the package still ships only `blue-fantasy`.

> **Compatibility**: one tightening comes first here: the `dsh.engines.dsh` floor and the `@deepseek-ai/dsh` peer floor move from `>=0.2.1-rc.3` to `>=0.2.2-rc.1`, so a host below that version cannot install 0.4.15 and has to be upgraded to 0.2.2-rc.1 or later first. Beyond that this release is not a breaking change and nothing has to be migrated by hand: the package name `@linxin666/dsh-client-ui-skin-center`; the install path (`dsh plugin --profile <name> add` and the `$DSH_HOME/skins/<id>` directory layout); the npm `files` whitelist, which still ships only `blue-fantasy`; the persisted file name and keys of the v2 active-state document; the semantic attribute names such as `data-dsh-skin` and `data-dsh-part`; and the wire fields. A saved custom-theme profile keeps every field it has, and the generated CSS simply loses one retired token declaration. In the semantic attribute contract the five git-graph part rows leave with the plugin and one `diagram` row arrives.

### New Features

- Follow the DSH 0.2.2 cohort (932b010, 47705d4): the SDK development dependencies pin to 0.2.2-alpha.3 first and then to 0.2.2-rc.1, Cordis to `^4.1.0` and schemastery to `^3.19.0`, the `dsh.engines.dsh` floor and the `@deepseek-ai/dsh` peer floor move to `>=0.2.2-rc.1` with them, and the CI and release workflows move Node from 22 to 24.9.0. Cordis changed its event typings, so `ctx.on` in `src/client/web-extension-page.ts` takes erased parameter types plus one cast at its call site, and the `slots/changed` reconciliation behaves as before. The official token snapshot is regenerated from `dsh-client-ui-theme@0.2.2-rc.1` and `dsh-web-frontend@0.2.2-rc.1` and grows from 329 entries to 335: six illustration tokens arrive (`--dsw-alias-illustration-background`, `-backing`, `-detail`, `-inset`, `-shadow`, `-surface`) with `--dsw-alias-state-done-primary`, and `--dsw-specific-sidebar-nav-item-hover`, which the official shell has withdrawn, leaves; the README badge and the bilingual pairing hashes move together

### Bug Fixes

- The readout strip becomes one sheet (c616ade): the host renders the context ring as a sibling of the `[data-slot="conversation.composer.dock"]` wrapper rather than a child of it, and the old form drew the paper shell on the slot wrapper, which left the ring outside the panel's right edge and made the strip read as two separate pieces. The shell is now drawn on the `[data-composer-dock]` container, with the two readouts on the left and the context ring on the right on the same sheet; the right-alignment rule written for the attribute `[data-dsh-live-tps]`, which does not exist, goes with it
- The context ring stops reading as a patch stuck on the sheet's right end (8737ca7): the shell theme paints the ring's trigger with a pill fill and radius of its own, and that rule outranks the button's own transparent background. The ring's whole subtree now resets `background` and `box-shadow`, keeping only the gold divider, so the ring and the two readouts sit on the same sheet
- The readout strip becomes one row sized to its content (4c827c1, 026b491): the two readout pills sit side by side with a gold hairline between them and the context ring closes the line on the right, so the line reads as one status rather than two separate readings; it wraps whole when the composer is too narrow, keeping the readings intact. The width changes from filling the composer to `width: max-content` capped at `max-width: 100%`, and the three cells group from the left, so the wide blank in the middle is gone
- The custom theme stops emitting a retired token (47705d4): after the official shell withdrew `--dsw-specific-sidebar-nav-item-hover` in 0.2.2, `src/core/custom-theme.ts` still generated that declaration in both the light and the dark block. `OFFICIAL_TOKENS` only accepts tokens taken from the official packages and never invents one, so the generating side changed instead: `CUSTOM_THEME_ALLOWED_TOKENS` and `declarations()` drop the entry together (sidebar hover already runs on `--dsw-alias-interactive-bg-hover`), which makes the official-token contract assertion in `tests/custom-theme.spec.ts` hold again. Skins that still declare the token do not pass through that table and are unaffected

- The contract registers the diagrams plugin and its diagram part (be28253): the new dsh-diagrams renders mermaid fences into a container of its own, so the contract gains the `diagrams` plugin row and the `diagram` part it owns (`[data-dsh-plugin="diagrams"][data-dsh-part="diagram"]`, painted by the mermaid SVG itself, with the raw code fence only hidden and outside the skinnable surface).
