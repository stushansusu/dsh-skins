皮肤中心发布 0.4.12，沿用 dsh-web 家族的统一版本号。本版本收的是两件事：atelier 系列三处可见缺陷的修复（手机宽度下的主视觉、浅色主题底部座位的墨色、皮肤中心状态胶囊的对比度），以及 DIY手账本插画的个人非商业使用声明与对应证据。皮肤目录仍是 62 套，钩子记录与 npm 白名单都不动，包内照旧只内置 `blue-fantasy`。

> **兼容性**：本版本没有破坏性变更，没有需要手工迁移的改动，没有重命名任何已持久化的标识符、线协议字段或 profile 格式。以下标识是冻结的：包名 `@linxin666/dsh-client-ui-skin-center`；安装方式（`dsh plugin --profile <name> add` 与 `$DSH_HOME/skins/<id>` 目录布局）；npm `files` 白名单仍只内置 `blue-fantasy`；v2 活跃状态文档的持久化文件名与键名；`data-dsh-skin`、`data-dsh-part` 等语义属性名；线协议字段。`dsh.engines.dsh` 下限保持 `>=0.2.1-rc.3` 未动，与 0.4.11 一致。

### 修复

- 手机宽度下的 atelier 主视觉（83abadc）：maid-atelier 与 phoebe-atelier 都照抄了宿主的桌面内容下限 `--dsh-chat-content-width: clamp(560px, 41vw, 740px)`，它在 1366px 以下恒等于 560px，于是 390px 手机上的主视觉被排进 560px 的盒子：phoebe 的三栏标题把第三栏（预览徽标）压进标题里，maid 的徽标按 `left: calc(100% + 8px) !important` 挂在标题右缘之外、直接溢出视口。两套皮肤各自新增 `@media (max-width: 480px)` 块，把下限放开到 `100%`、给标题 `min-width: 0`，并让预览徽标改用自己的 `max-width: 100%` 摆放。做成一皮肤一块而不是共享样式表，因为皮肤是自包含的资产目录，共享表会把两个独立发布的皮肤耦在一起
- phoebe-atelier 底部座位的墨色（83abadc）：浅色主题侧边栏改画象牙壁柱之后，底部座位 `[data-slot='sidebar.footer.action']` 仍留着给已退役深蓝面板写的近白标签色，而座位是宿主的扩展边界、挂上去的卡继承它的文字而不是自绘，于是象牙底上落了瓷白字，实测 1.08:1。修法是把瓷白色板从座位根移到两个自绘深蓝盘面的叶子控件（设置触发器与 `[data-cordis-badge]`），座位根只保留表面、描边与悬停令牌、不再声明标签色，由 `body:not([data-ds-dark-theme])` 作用域给它象牙底墨色（`#17284f`、`#3a4361`、`#48526f`、`#56617c`）；深色主题仍是深蓝夜画廊，瓷白墨在那里本来就是对的
- 皮肤中心三个状态胶囊（83abadc）：`.badgeActive`、`.badgeTrying` 与 `.delegatedBadge` 的文字取 `--dsw-alias-brand-primary` 与 `--dsw-alias-state-success-primary` 这类提示色，皮肤并不把这些令牌与标签令牌一起重映射，所以在 maid-atelier 或 phoebe-atelier 下胶囊留着宿主墨色、卡片正文却跟着皮肤走。三处文字改用 `--dsw-alias-label-primary`，语义绿与语义蓝只留在填充里，并且三个胶囊都补了 1px 令牌描边——只有委派胶囊原本带描边，另两个只靠填充对比度撑着，边缘在近似卡面的填充上会消失。深色主题的 trying 胶囊保留语义蓝，填充换成 `--dsw-alias-state-business-tertiary`，实测约 8.8:1（旧的中蓝盘面在真实 GUI 里只有 3.60:1）
- maid-atelier 顶部饰带把页面撑出横向滚动（83abadc）：`hooks.mjs` 追加的 body 级饰带横跨整个窗口，再按侧边栏宽度把自己向右平移，于是它自己的盒子越过视口一个侧边栏宽（390 视口配 52px 导轨时 `x=52 / width=390 / right=442`，1440 配 280px 侧边栏时 `right=1720`）。改成把饰带夹在侧边栏边缘与窗口右缘之间（`left: var(--maid-sidebar-width, 280px)`、`right: 0`、`width: auto`，去掉水平 `translate`），冠饰蝴蝶结的 `left` 计算同步减掉它过去重复扣的侧边栏宽度。下层仍按 `repeat-x` 铺满内容区，表面画法不变，也没有裁剪或隐藏内容；把这条饰带单独隐藏后 `documentElement.scrollWidth` 才回到视口，正是这一步把责任锁定在它的盒子几何上
- 手机宽度的两处窄屏卫生（83abadc）：宿主的列宽拖拽手柄用 `left: calc(50% + var(--dsh-chat-content-width) / 2 + 24px)` 定位、用 `min(10px, calc((100% - var(--dsh-chat-content-width)) / 2 - 48px))` 定尺寸，活动期还会把该令牌下限抬到 680px，所以在 390px 屏幕上它落在右缘之外，负宽度又让尺寸声明失效而非得到一个零宽命中区，因此 480px 及以下不再渲染 `[data-width-handle]`；`.dock` 是居中 flex 行、芯片 `white-space: nowrap` 且 `flex: none`，宽条会横向溢出而不折行，所以 `[data-composer-dock]` 在 480px 及以下折行，既不隐藏也不裁剪，折行只在整行放不下时生效，折叠态的每个芯片与它自己的状态都还在。这两项按窄屏卫生记录，不是 442 那次的修复对象
- 回归测试（83abadc）：新增 `tests/atelier-hero-phone.spec.ts` 与 `tests/maid-phoebe-label-contrast.spec.ts`，并扩写 `tests/maid-atelier-patches.spec.ts`。它们是静态测试，钉住声明并自行计算对比度比值，看不到真实的 390px 布局，所以真实宿主上的 390px 目视验收仍留在 QA 轮

The skin center publishes 0.4.12 on the family's shared version line. It carries two things: fixes for three visible defects in the atelier skins (the hero at phone widths, the light-theme footer seat ink, and the contrast of the skin center's state pills), and the personal non-commercial artwork statement for DIY Journal together with its evidence. The catalog still holds 62 skins, the reviewed-hooks record and the npm whitelist do not move, and the package still ships only `blue-fantasy`.

> **Compatibility**: this release is not a breaking change. There is nothing to migrate by hand, and no persisted identifier, wire field or profile format was renamed. These identifiers are frozen: the package name `@linxin666/dsh-client-ui-skin-center`; the install path (`dsh plugin --profile <name> add` and the `$DSH_HOME/skins/<id>` directory layout); the npm `files` whitelist, which still ships only `blue-fantasy`; the persisted file name and keys of the v2 active-state document; the semantic attribute names such as `data-dsh-skin` and `data-dsh-part`; and the wire fields. The `dsh.engines.dsh` floor stays at `>=0.2.1-rc.3`, as in 0.4.11.

### Bug Fixes

- The atelier hero at phone widths (83abadc): both maid-atelier and phoebe-atelier copied the host's desktop content floor, `--dsh-chat-content-width: clamp(560px, 41vw, 740px)`, which resolves to 560px at any width below 1366px, so the hero on a 390px phone was laid out inside a 560px box: phoebe's three-column headline pushed its third column (the preview badge) into the title, and maid's badge, hung off the title's right edge with `left: calc(100% + 8px) !important`, overflowed the viewport. Each skin gains its own `@media (max-width: 480px)` block that releases the floor to `100%`, sets `min-width: 0` on the headline, and gives the preview badge a `max-width: 100%` placement of its own. It is one block per skin rather than a shared stylesheet because a skin is a self-contained asset directory, and a shared sheet would couple two independently published skins
- phoebe-atelier's footer seat ink (83abadc): after the light-theme sidebar became an ivory pilaster, the footer seat `[data-slot='sidebar.footer.action']` kept the near-white label palette written for the retired navy panel, and because the seat is the host's extension boundary whose mounted card inherits its text instead of painting it, porcelain ink landed on the ivory plate at a measured 1.08:1. The fix moves the porcelain palette off the seat root and onto the two leaf controls that paint their own navy plate (the settings trigger and `[data-cordis-badge]`); the seat root keeps its surface, border and hover tokens and declares no label palette at all, and a `body:not([data-ds-dark-theme])` block hands it the ivory-surface ink (`#17284f`, `#3a4361`, `#48526f`, `#56617c`). The dark theme still paints a navy night gallery, where the porcelain ink was correct all along
- The skin center's three state pills (83abadc): `.badgeActive`, `.badgeTrying` and `.delegatedBadge` took their text from affordance colours such as `--dsw-alias-brand-primary` and `--dsw-alias-state-success-primary`, which a skin does not remap together with its label tokens, so under maid-atelier or phoebe-atelier the pill kept the host's ink while the card's body text followed the skin. All three now paint their text with `--dsw-alias-label-primary`, keeping the semantic green and blue in the fill, and each carries a 1px token border - only the delegated pill had one, and the other two leaned on fill contrast alone, so their edge vanished on a fill a skin tints close to the card surface. The dark-theme trying pill keeps the semantic blue but fills it with `--dsw-alias-state-business-tertiary`, measuring about 8.8:1; the previous mid-blue plate measured 3.60:1 in the real GUI
- maid-atelier's top trim put the page into horizontal scroll (83abadc): the body-level band `hooks.mjs` appends spanned the whole window and then shifted itself right by the sidebar width, so its own box ended one sidebar width past the viewport (`x=52 / width=390 / right=442` at a 390 viewport with the 52px rail, `right=1720` at 1440 with the 280px sidebar). The band is now pinned between the sidebar edge and the window's right edge (`left: var(--maid-sidebar-width, 280px)`, `right: 0`, `width: auto`, with the horizontal `translate` removed), and the crest bow's `left` calc drops the sidebar width it used to subtract a second time. The layers below still `repeat-x` across the content area, the painted surface is unchanged, and nothing is clipped or hidden; hiding this band alone returned `documentElement.scrollWidth` to the viewport, which is what identified its box geometry as the owner
- Two narrow-viewport hygiene changes at phone widths (83abadc): the host positions its column-resize handles with `left: calc(50% + var(--dsh-chat-content-width) / 2 + 24px)` and sizes them with `min(10px, calc((100% - var(--dsh-chat-content-width)) / 2 - 48px))`, and its active phase floors that token at 680px, so on a 390px screen the strip lands past the right edge and the negative width makes the sizing declaration invalid rather than the zero-width hit area the host intends, so `[data-width-handle]` is not rendered at or below 480px; `.dock` is a centered flex line whose chips are `white-space: nowrap` and `flex: none`, so a wide strip overflowed sideways instead of wrapping, so `[data-composer-dock]` wraps at or below 480px - neither hidden nor clipped, and the wrap only engages when the line does not fit, keeping every chip and its own state. Both are recorded as narrow-viewport hygiene, not as the fix for the 442 overflow
- Regression tests (83abadc): new `tests/atelier-hero-phone.spec.ts` and `tests/maid-phoebe-label-contrast.spec.ts`, plus an extension of `tests/maid-atelier-patches.spec.ts`. They are static: they pin the declarations and compute the contrast ratios themselves, and cannot see a real 390px layout, so the visual pass on a real host at 390px stays part of the QA round
